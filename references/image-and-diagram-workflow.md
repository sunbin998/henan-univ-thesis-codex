# 图表、图片替换与截图工作流

用于论文图表重绘、软件工程图审查、DOCX 既有图片替换和真实系统截图插入。

## 图表质量

- 图表必须清晰、正式，颜色统一。
- 箭头、连线、标签不能遮挡文字。
- 软件工程图应符合基本表达规范。
- ER 图应区分实体、属性和联系。
- 图题格式优先统一为 `图X-Y 图名`，表题统一为 `表X-Y 表名`。
- 图表要在正文中自然引用，不要只孤立摆放。

## 替换 DOCX 中已有图片

当目标位置已有图片和图题时，优先替换 DOCX 内部媒体文件：

1. 备份主文档。
2. 用 `python-docx` 定位目标图题附近的 `w:drawing`。
3. 读取 `a:blip` 的 `r:embed` 关系 ID。
4. 通过 `doc.part.related_parts[rid].partname` 得到内部媒体路径，如 `/word/media/image14.png`。
5. 直接替换 DOCX zip 中对应 `word/media/imageX.png` 的二进制内容。
6. 保持原文件名不变，以保留 Word 中的尺寸、位置、图题和分页。
7. 替换后再次检查 drawing 仍指向同一媒体文件，并确认 blob 大小已变化。
8. 导出 PDF 并检查目标页。

不要只修改外部 `diagrams/*.png`。DOCX 图片是嵌入关系，外部 PNG 更新不会自动同步到 Word。

## 真实浏览器截图

需要把系统真实界面截图插入论文时，优先使用主机 Windows Chrome + Playwright：

- 可访问 `http://localhost:3000/workspace` 等本地前端页面。
- 使用用户已有测试账号，不要新建无关账号。
- 截图应体现系统主题，如日记、知识库、RAG 来源、分类标签、对话管理、搜索等。
- 不要选择只有 `hi`、空白对话或主题很弱的页面。
- 截图保存到项目 `diagrams/` 后，先打开图片检查清晰度、隐私信息和构图。
- 插入或替换到 DOCX 后必须导出 PDF 验收。

## 截图选择

RAG 来源截图应能看到用户问题、AI 回答片段和展开的参考来源卡片。知识库、日记、分类、搜索截图应显示功能正在被使用，而不是只截入口按钮。
