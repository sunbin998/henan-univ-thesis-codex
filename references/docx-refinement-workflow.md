# DOCX 精修流程

用于现有河南科技大学本科毕业论文已经进入人工精修阶段时。目标是小范围、可验证地改好当前 `.docx`，避免整篇重生成覆盖已经修好的格式。

## 默认原则

1. 优先直接编辑主文档 `.docx`。
2. 不默认运行整篇生成脚本。
3. 只有需要批量重建目录、表格、图题、参考文献或用户明确要求时，才考虑脚本。
4. 重要修改前创建语义备份，不覆盖旧备份。
5. 使用 `python-docx` 或直接编辑 OOXML 后，都要检查实际 XML 结果，而不是只看程序返回值。

## 修改前检查

- 确认目标文档和批阅版文件。
- 查学校规范、官方模板、往年范例和本 skill 的格式样本。
- 判断修改是否会影响分页、目录、图表、页眉页脚、参考文献或章节编号。
- 如果用户只要求局部修改，保持改动范围最小。

## 格式审计清单

- run 级中文字体是否写入 `w:eastAsia`。
- 英文和数字是否为 Times New Roman。
- 字号是否与规范一致。
- 不该加粗的标题和正文是否清理了直接加粗。
- 正文首行缩进是否为 2 字符。
- 行距是否为单倍行距。
- 节、子节标题是否顶格，段前段后是否为 0.5 行。
- 表题、表头、表内文字是否分别使用学校规定字体字号。
- 页眉页脚、页码类型、分节符是否被意外改动。

## 跨页问题

跨页正文和跨页表格不要靠插空行硬凑。优先检查：

- 段落 `keep_together`、`keep_with_next`、`widow_orphan_control`。
- 表格行 `cantSplit`。
- 表头重复设置。
- 首行缩进与续页视觉起点。
- 同一逻辑对象是否被拆成不自然的残片。

## 交付前

至少完成结构检查、字体字号检查和 PDF 渲染检查。无法完成渲染时，要在结果中说明原因和剩余风险。
